Lime Personal Accounting — A WordPress Plugin Case Study

Building a lightweight, self-hosted personal accounting system inside WordPress

1. The Problem

Most personal finance tools are either cloud-based SaaS products (with recurring costs and privacy concerns) or overly complex desktop applications. For freelancers, small business owners, and individuals who already manage their digital presence through WordPress, there was no simple, integrated solution for tracking day-to-day income and expenses without leaving their familiar dashboard.

The goal was to build a self-hosted, privacy-first personal accounting plugin that lives entirely within the WordPress admin panel — no external APIs, no third-party tracking, no subscription fees.

3. Architecture Overview

The entire system runs as three Docker containers orchestrated via docker-compose.yml:

  • lime_lpa_app — WordPress on PHP 8.5/Apache, serving the plugin on port 8090
  • lime_lpa_db — MySQL 8.0 with persistent volume storage
  • lime_lpa_phpmyadmin — phpMyAdmin on port 8091 for direct database inspection

The plugin code is volume-mounted directly into the WordPress container, enabling live development without rebuilds.

4. Database Design

The plugin creates 6 custom tables with the lpa_ prefix, all following a consistent schema pattern with soft-delete support:

Table Purpose Key Columns
lpa_wallets Financial accounts/categories name, category (income/expense)
lpa_incomes Income transactions fk_wallet_id, amount, description, currency
lpa_expenses Expense transactions fk_wallet_id, amount, description, currency
lpa_cashbook Auto-generated transaction ledger in_amount, out_amount, fk_reference_id, reference_type
lpa_activities Audit trail type, name, ip_address, geo fields
lpa_configurations Plugin settings name (unique), setting (JSON text)

Design Decisions:

  • Soft Deletes: Every table includes a deleted_at column. Records are never physically removed; they are marked with a timestamp. This ensures data recoverability and maintains referential integrity in the cashbook.
  • Auto-timestamps: All tables track created_at, created_by, updated_at, and updated_by for full audit trails.
  • Cashbook Normalization: Income and expense entries automatically generate corresponding cashbook records, creating a single unified ledger without manual entry.

5. Plugin Architecture

The plugin follows a modular WordPress architecture with clear separation of concerns:

5.1 Main Entry Point (lime-personal-accounting.php)

The bootstrap file defines constants, loads modules, registers activation/deactivation hooks, and wires up asset enqueuing. On activation, it calls lpa_create_tables() to set up the database schema via dbDelta().

5.2 Admin Menu System (includes/admin-menu.php)

Registers a top-level "Accounting" menu with 7 subpages: Dashboard, Wallets, Incomes, Expenses, Cashbook, Activities, and Settings. All pages require the manage_options capability.

5.3 AJAX Router (includes/ajax-handlers.php)

A single AJAX endpoint (wp_ajax_lpa_action) routes all requests through a switch-based dispatcher. The router handles 12 actions across wallets, incomes, expenses, cashbook, activities, and settings. Security is enforced via nonce verification and capability checks on every request.

5.4 Page Controllers (includes/pages.php)

Each page function fetches necessary data (dashboard computes totals) and includes the corresponding view template.

5.5 View Templates (includes/views/)

Minimal PHP templates that output HTML structure with CSS classes. Data is loaded client-side via AJAX, keeping templates clean and enabling dynamic updates without page reloads.

6. Key Features Deep Dive

6.1 Wallet Management

Wallets serve as the foundational entity. Each wallet has a category — either income or expense — which determines where it appears in dropdown selectors. When creating an income, only wallets categorized as "income" are shown, and vice versa. This prevents misallocation of transactions.

6.2 Income & Expense Tracking

Both income and expense forms capture: wallet (filtered by category), amount (decimal with 2 places), description (free-text), and currency (text field, defaults to USD). The system supports multi-currency tracking without conversion — each transaction records its original currency.

6.3 Automatic Cashbook Generation

This is the plugin's core innovation. When a new income is created:

  1. A record is inserted into lpa_incomes
  2. A corresponding record is automatically inserted into lpa_cashbook with in_amount populated and reference_type = 'income'

When an expense is created, the same dual-write happens with out_amount. When either is deleted, both records are soft-deleted simultaneously. This ensures the cashbook always reflects the true state of all transactions.

6.4 Activity Logging

Every income/expense creation triggers lpa_log_activity(), which records the admin user, action type (success for income, warning for expense), description, IP address, and timestamp. The activities page shows the last 50 entries.

6.5 Dashboard Analytics

The dashboard computes three key metrics from raw SQL queries:

  • Total Income — Sum of all non-deleted income records
  • Total Expense — Sum of all non-deleted expense records
  • Balance — Income minus Expense

Transaction counts and wallet counts are also displayed as supplementary context.

7. Frontend Implementation

The frontend uses a jQuery SPA-like pattern within the WordPress admin context:

7.1 AJAX Helper

A centralized lpaPost() function handles all server communication, automatically including the action type, nonce, and data payload. Error handling is built-in with toast notifications.

7.2 Modal System

Create/edit operations use fixed-position modals with overlay. The same modal serves both create and edit — the title and hidden ID field are updated dynamically. Wallet selection dropdowns are populated in real-time from the server.

7.3 Table Rendering

Data tables are built client-side from AJAX responses using template strings. Each table includes inline action buttons (Edit, Delete) with confirmation dialogs. Empty states show helpful prompts when no data exists.

7.4 Toast Notifications

Non-intrusive toast messages appear in the bottom-right corner for 3 seconds, using CSS transitions for smooth enter/exit animations. Color-coded by type (green for success, red for error).

7.5 Auto-Initialization

On document.ready, the script detects which page is active by checking for specific DOM element IDs and loads the corresponding data automatically. No manual initialization code is needed per page.

8. Security Measures

  • Nonce Verification: Every AJAX request must include a valid lpa_nonce token, verified server-side via check_ajax_referer()
  • Capability Checks: All operations require manage_options capability (admin-level access)
  • Input Sanitization: All user inputs are sanitized using WordPress functions: sanitize_text_field(), sanitize_textarea_field(), absint(), floatval()
  • ABSPATH Checks: Every PHP file begins with if (!defined('ABSPATH')) exit; to prevent direct access
  • Parameterized Queries: All database operations use the WordPress $wpdb API with prepared statements, preventing SQL injection

9. CSS Design System

The plugin uses a custom design system with 400+ lines of CSS built around these principles:

  • CSS Grid for responsive stat cards (auto-fit with minmax)
  • CSS Variables via class-based theming — consistent color palette (green for income, red for expense, blue for balance)
  • 12px border-radius throughout for a modern, rounded aesthetic
  • Subtle shadows (0 2px 8px rgba(0,0,0,0.06)) for depth without heaviness
  • Mobile-first responsive — tables scroll horizontally on small screens, grid collapses to single column
  • Badge system — pill-shaped labels for status indicators (income, expense, success, warning, error)

10. Docker Deployment

The system is containerized with docker-compose for one-command deployment:

docker-compose up -d

This starts all three services. The plugin source code is volume-mounted from the host, meaning any code change is reflected immediately without rebuilding the container. The MySQL data persists in a local db_data/ directory.

Ports:

  • 8090 — WordPress + Plugin
  • 8091 — phpMyAdmin

12. Challenges & Solutions

Challenge Solution
Maintaining a unified ledger alongside individual transactions Dual-write pattern: every income/expense save also writes to cashbook in the same request
Data integrity on deletion Soft deletes with cascading: deleting income also soft-deletes the linked cashbook entry
Preventing wallet misuse (income wallet for expenses) Client-side filtering: wallet dropdowns only show wallets matching the current form's category
Page-specific asset loading admin_enqueue_scripts hook checks current screen ID for lpa_ prefix before loading
AJAX security in WordPress Combined nonce verification + capability check + input sanitization on every request

14. Conclusion

Lime Personal Accounting demonstrates that a fully functional personal finance tool can be built as a lightweight WordPress plugin with zero external dependencies. By leveraging WordPress's built-in capabilities (admin UI, AJAX, database abstraction, user management) and adding a clean frontend layer, the plugin delivers a complete accounting experience that is:

  • Self-hosted — all data stays on your server
  • Privacy-first — no third-party tracking or cloud dependencies
  • Zero-cost — no subscription fees or premium tiers
  • Extensible — clean architecture makes adding features straightforward

The Docker-based deployment ensures reproducibility across environments, making it equally suitable for personal use, client projects, or as a foundation for more complex financial applications.
